Use PASSAGE

Software guide

Install the R package, prepare aligned inputs, and run the testing workflow that answers your question.

Install

Use R 4.1 or later. Install from GitHub, with irlba for fast global PCA on larger gene backgrounds:

install.packages(c("remotes", "irlba"))
remotes::install_github("diptavo/PASSAGE")
library(PASSAGE)
packageVersion("PASSAGE")

The core package requires Matrix. Pathway PCA, factor analysis and the GP comparison need no additional packages. Optional descriptive fits require GpGp and fields; the separate joint-factor engine requires TMB, RcppEigen and a working C++ compiler.

Start with a prepared sample. The KC2 example is included in the installed package. It runs estimation, both self-contained routes and competitive testing without downloading another dataset.

Prepare your inputs

A PASSAGE bundle is an ordinary R list. Normalize expression and establish the adjustment design before creating it. The names below stand for your prepared matrices:

bundle <- list(
  Y = expression_matrix,       # spots x genes
  coords = coordinate_matrix, # spots x spatial dimensions
  X = design_matrix,          # spots x covariates; NULL for intercept only
  pathway_sets = list(
    pathway_A = pathway_A_genes,
    pathway_B = pathway_B_genes
  ),
  sample = "sample_01"
)
bundle <- passage_validate_bundle(bundle)
saveRDS(bundle, "sample.rds")
InputRequired structure
YFinite normalized expression, spots in rows and genes in columns. Unique spot IDs and gene names. Keep the full eligible gene universe for competitive testing.
coordsFinite, unique coordinates. Row names must match the spot IDs in Y, in exactly the same order.
XFinite, full-rank covariate design with matching spot names and order. An intercept is added if absent. Omit one composition fraction when fractions sum to one and an intercept is present.
pathway_setsA named list of gene vectors, using the same gene identifiers as colnames(Y). Keep the intended gene lists so missing-gene coverage can be reported.

Validation checks dimensions, identifiers, alignment and finite values; it does not normalize raw counts or establish model assumptions. A bundle needs at least 10 spots and five genes. Pathway fitting needs at least two observed genes with nonzero adjusted variance. Competitive testing defaults to observed pathway sizes of 15–500 and requires sufficient matched background genes.

Optional cell_type_proportions records all aligned fractions and checks their row sums. It does not automatically add them to X. Choose adjustment columns explicitly.

Estimate and test one pathway

The following assumes that sample.rds contains the bundle above. Scale coordinates with one common factor so the tissue aspect ratio is preserved:

library(PASSAGE)
b <- passage_validate_bundle("sample.rds")

xy <- sweep(b$coords, 2, apply(b$coords, 2, min), "-")
xy <- xy / max(xy)

fit <- passage_fit_pathway(
  b$Y, b$pathway_sets[["pathway_A"]], X = b$X,
  method = "pca", variance_threshold = 0.95
)

test <- passage_test_pathway_gp(
  fit, coords = xy,
  ranges = c(0.05, 0.1, 0.2, 0.4),
  kernel_method = "lowrank", n_features = 64,
  B = 9999, seed = 1
)

test$p
test$component_fits
fit$K
fit$missing_genes
fit$dropped_genes
saveRDS(list(fit = fit, test = test), "pathway_result.rds")

The R API uses the coordinate units supplied. Here, the longest axis spans one, so the range grid is in those units. fit$scores contains spot activity and fit$loadings contains gene contributions. The test uses these unsmoothed scores.

Estimation choices

# Fixed-rank PCA
fit <- passage_fit_pathway(
  b$Y, b$pathway_sets[["pathway_A"]], X = b$X,
  method = "pca", K = 2
)

# Maximum-likelihood factor analysis
fit_fa <- passage_fit_pathway(
  b$Y, b$pathway_sets[["pathway_A"]], X = b$X,
  method = "factor_analysis", K = 2
)

FA requires a fixed, identifiable rank and a nonsingular gene correlation matrix. A rank suitable for PCA is not automatically suitable for FA. Either fit can be passed to the pathway GP test when those requirements are met.

Kernel and simulation choices

SettingHow to choose it
kernel_methodlowrank keeps all spots with a Nyström kernel approximation. dense provides a reference for smaller data; its default limit is 1,000 spots.
n_features64 is a starting point, not an accuracy guarantee. Compare prespecified feature counts and a dense reference where affordable.
rangesA positive grid in the supplied coordinate units. Decide it before inspecting results.
fractionsDefaults to c(0, .01, .025, .05, .1, .25, .5, .75, .9, .97). A custom grid must include zero and stay below one.
B199 is useful for an execution check. 9,999 allows a raw p-value floor of 0.0001. Choose enough draws for your multiple-testing threshold.

Reuse coordinate work across pathways

cache <- passage_prepare_gp_kernel(
  xy, X = b$X,
  ranges = c(0.05, 0.1, 0.2, 0.4), n_features = 64
)
test <- passage_test_pathway_gp(
  fit, kernel_cache = cache, B = 9999, seed = 1
)

Reuse a cache only for the same spots, order and adjustment design. Cache settings govern the test; conflicting explicit settings produce an error.

Choose component aggregation or unequal-noise calibration

The Gaussian rotation test accepts aggregation = "sum" (default), "max" or "topk", with top_k specifying the last option’s count. The selected aggregation is repeated in every reference draw.

For the approximate wild-bootstrap alternative, supply expression and the pathway so estimation can be refitted for every draw:

wild <- passage_test_pathway_gp_wild(
  b$Y, b$pathway_sets[["pathway_A"]], coords = xy, X = b$X,
  method = "pca", K = 2, aggregation = "sum",
  ranges = c(0.05, 0.1, 0.2, 0.4), n_features = 64,
  B = 9999, seed = 1
)
wild$p
wild$max_leverage
wild$component_fits

This retains spot-specific residual magnitudes with HC2 leverage adjustment. It requires independent spot errors and a suitable mean model, and does not provide exact finite-sample guarantees. Refitting every draw costs more than the conditional rotation procedure. See the calibration guide for assumptions and validation.

Run the fixed-kernel alternative

fixed <- passage_test_pathway_fit(
  fit, coords = xy, kernel_range = 0.25,
  B = 9999, seed = 1
)
fixed$p
fixed$p_omnibus_bonferroni

This tests trace and largest-root alignment at a prespecified spatial range. The omnibus corrects over those two statistics only. This dense implementation has a default 3,000-spot limit and does not silently subset the data. If also running the GP comparison, decide which is primary before inspecting results.

Run competitive analysis

b <- passage_validate_bundle("sample.rds")
competitive <- passage_analyze_bundle(
  b, B = 9999, seed = 1, reference = "universe"
)
competitive$summary
competitive$coverage
saveRDS(competitive, "competitive_result.rds")

This explicitly chooses full-universe randomization, allowing target overlap under the conditional gene-label null. Omitting reference retains the earlier "complement" default, which excludes target genes. The default estimator remains global PCA with six factors and 20 Vecchia neighbors. Keep a broad eligible gene universe in Y.

The main summary fields include p_competitive, q_BH, q_BY, score_excess and candidate_drivers. competitive$tests includes every requested statistic and combination. BH/BY adjustments cover pathways within each named test, not selection across tests or combiners. Define a larger family if multiple samples or test choices belong to the same claim.

If matching fails, inspect coverage and the matching strata. Custom gene_bins must contain gene and bin, with optional module, in exactly the order of the nonconstant expression columns. Do not replace a failed matched comparison with an unmatched result without redefining the analysis.

Choose global statistics or pathway-local estimation

# Global loading, directional activity and sparse-gene evidence
panel <- passage_analyze_bundle(
  b, B = 999, seed = 1, reference = "universe",
  statistics = c("score_z", "score_activity_hotspot", "score_sparse_topk_z"),
  combine = "minp"
)
panel$tests

# Refit pathway PCA and GP statistics for every matched set
local <- passage_analyze_bundle(
  b, B = 999, seed = 1, reference = "universe",
  estimation = "pathway", local_method = "pca", local_K = 3,
  gp_aggregations = c("sum", "max"), combine = "minp"
)
local$tests

For factor analysis use local_method = "factor_analysis" and an identifiable fixed local_K. Global rank options include rank_method = "variance", variance_threshold, max_K, and a prespecified rank_grid for fixed-rank sensitivity panels. Inspect competitive$estimation for the fitted ranks and diagnostics. Candidate drivers and global covariance metrics are supplied for global fits; they are not populated for pathway-local fits.

combine can be "none", "minp", "cauchy" or "fisher". Combinations use empirical calibration on shared reference sets. The first requested combination, or otherwise first statistic, defines the bundle’s primary summary. Prespecify that ordering.

For custom statistics, use passage_competitive_test() with a deterministic function of gene indices. passage_make_statistic() supplies global statistics and passage_make_local_gp_statistic() supplies local ones. The complete interface guide lists all 18 global choices and explains matching diagnostics, custom callbacks and Monte Carlo intervals.

Add prespecified nuisance controls

adjustment <- passage_prepare_nuisance(
  b$Y, X = b$X, control_genes = negative_controls, n_factors = 2
)
adjustment$diagnostics
b$X <- adjustment$X
b$Y <- b$Y[, adjustment$analysis_genes, drop = FALSE]
# Rebuild the estimation and matching with this adjusted bundle.

negative_controls must be a prespecified vector of defensible control-gene names. The helper cannot identify valid biological controls for you. Controls are excluded from the returned analysis universe; treating their estimated PCs as fixed does not propagate their uncertainty.

Optional descriptive fits

install.packages(c("GpGp", "fields"))
descriptive <- passage_fit_pathway_gp(fit, xy)
descriptive$summary

This reports component covariance estimates and convergence from GpGp. It does not return a spatial-test p-value or provide inputs to the tests above. The main GP comparison fits its own parameters.

Advanced fitting engines are described in the Methods page. They use passage_fit_factor_engine() or the separate passage_fit_joint_factor_tmb() interface. They require a custom lower-level workflow, and coordinate-informed scores need their own inferential calibration.

Use the command line

For the bundled dataset, use the short commands on the Example analysis page. Those commands retain their established defaults: Gaussian rotations for the GP test and global score_z with complement references for competitive analysis. Use the R functions above to select wild refitting, full-universe references, local competitive estimation or statistic panels. For your own bundle, run these legacy commands from the installed source checkout’s PASSAGE directory:

# Pathway GP comparison
Rscript inst/scripts/passage_pathway_cli.R sample.rds pathway_A gp_results \
  9999 1 pca auto 0.25 false gp lowrank 64

# Fixed-kernel analysis
Rscript inst/scripts/passage_pathway_cli.R sample.rds pathway_A fixed_results \
  9999 1 pca auto 0.25 false subspace

# Competitive analysis; pathways.rds is a named list of gene sets
Rscript inst/scripts/passage_cli.R sample.rds pathways.rds competitive_results 9999 1
Pathway command argument order 
BUNDLE PATHWAY OUTPUT B SEED METHOD K RANGE DESCRIPTIVE_GP
TEST GP_KERNEL FEATURES RANGES FRACTIONS

pca auto keeps 95% of adjusted variance; pca 2 fixes two PCs; factor_analysis 2 requests two factors. RANGE is used only by the fixed-kernel test, but remains a positional argument for GP runs. DESCRIPTIVE_GP=true additionally runs the separate GpGp fits.

TEST is gp or subspace; omission defaults to subspace. The optional final two arguments are comma-separated range and fraction grids.

Use a new or empty output directory. The pathway CLI checks this; the older competitive CLI does not reject an existing directory. Both record the run settings and write analysis.complete after successful execution.

The competitive CLI writes passage_result.rds, pathways.csv and pathway_coverage.csv, alongside the session record and completion marker. The kidney runner combines routes in a single summary table and saves their detailed objects.

Interpretation is part of the workflow. Single-pathway functions do not adjust across pathways or samples. A completed run demonstrates execution, not calibration. Read the current variance assumptions, examine coverage and boundary flags, and record the testing family before drawing biological conclusions.

For argument-level help, use ?passage_fit_pathway, ?passage_test_pathway_gp and ?passage_analyze_bundle in R. The repository reference also documents the command-line interface.
